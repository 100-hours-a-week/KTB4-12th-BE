## 검증 범위와 한계

- 외부 AI 서버·DB 없이 JDK HttpServer와 embedded Tomcat을 사용한다. FE도 실제 HTTP 연결을 연다.
- transport 테스트는 로그인 ID 해석과 대화 접근을 stub/mock 처리한다. 실제 토큰·대화 접근 규칙은 기존 ChatConversationTokenProviderTest와 ChatConversationAccessServiceTest로 별도 검증한다. 실제 SecurityFilterChain까지 포함한 배포 인증 검증은 아니다.
- idle은 500ms로 축소하고 heartbeat는 200ms 간격으로 보내 테스트한다. 60초 설정에서도 close가 즉시 수행되는지는 별도 close 테스트로 확인한다.
- 전체 240초를 실제로 기다리지는 않는다. timeout 값 등록과 Servlet timeout/error 콜백의 정리를 검증한다.
- 준비 중 연결도 Semaphore 제한에 포함됨을 검증한다. 동시 연결 상한의 운영 수치는 부하 테스트로 결정해야 한다.
- 배포 프록시 버퍼링·압축·네트워크 장애와 실제 AI 계약 확인은 6단계에서 진행한다. 전체 main-backend 테스트는 아래 후속 검증에서 실행했다. payment-server 테스트는 이번 후속 검증 대상이 아니다.


## 전체 컨텍스트 설정 보완 및 재검증 — 2026-10-14

전체 테스트 결과 1,339개 중 455개가 실패했다. 최초 원인은 모두 `ChatSseProperties`의 필수 설정 누락이며, 나머지는 컨텍스트 재로딩 생략으로 연쇄 실패했다. `src/test/resources/application.yaml`은 실행용 파일을 대체하므로 `.env` 또는 실행용 YAML에 값을 추가하는 것만으로는 테스트 설정을 채울 수 없다.

테스트 YAML의 `app.ai-chat.sse`에 idle 60초, 전체 240초, 테스트용 연결 상한 10을 명시했다. 운영 연결 상한과 무관한 테스트 설정이다. 기존 테스트의 기대값은 변경하지 않았다.

```bash
./gradlew :main-backend:test
```

결과: **1,339개 통과, 실패·오류·건너뜀 0개**.
