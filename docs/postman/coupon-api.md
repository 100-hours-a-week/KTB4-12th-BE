# 쿠폰 PR 1 수동 검증

1. `coupon-api.postman_collection.json`과 `coupon-local.postman_environment.json`을 Postman에 가져온다.
2. 로컬 API 서버와 마이그레이션 적용을 확인한다. 로컬 테스트 회원의 `email`, `password`를 환경의 로컬 값으로 입력한다. 실제 토큰·비밀번호를 저장소에 기록하지 않는다.
3. `01 로그인 및 토큰 저장`부터 순서대로 실행한다. 기존 Access Token을 직접 설정했다면 01은 생략한다.
4. 수량 응답까지 비교하려면 `expectedCoupons`에 아래 JSON 중 실제 준비한 상태를 입력한다. 비워두면 응답 구조·배수·수량 범위·정렬·중복만 검사한다.

| 상태 | expectedCoupons |
| --- | --- |
| 두 종류 모두 0 | `[]` |
| 2배만 1개 | `[{"multiplier":2,"quantity":1}]` |
| 2배 2개·3배 1개 | `[{"multiplier":2,"quantity":2},{"multiplier":3,"quantity":1}]` |

수량 상태는 전용 로컬 테스트 계정으로 준비한다. 조회 요청은 DB를 변경하지 않는다. 공개 발급 API는 없으며 임시 발급 API도 추가하지 않는다.

## 자동 테스트가 담당하는 범위

- MySQL 통합 테스트: 초기화, 원자적 수량 증가·동시성, 트랜잭션 요구·롤백, DB 제약, 상한, 기존 회원 보완 SQL 재실행.
- 회원가입 테스트: 실제 가입 시 초기화 및 실패 시 회원·크레딧·쿠폰 롤백.
- MockMvc: 미인증·잘못된 토큰, 토큰 사용자별 조회, 0 제외·빈 결과, 정렬.

Postman 조회만으로 동시 발급·롤백·중복 지급을 검증했다고 판단하지 않는다. 실제 룰렛 중복 실행 방지는 Ava 구현 후 연동 검증한다.
